## 什么是A2A

A2A就是Agent2Agent, 是一个让不同AI智能体彼此通信和协作的开放标准, 由Google Cloud联合多家伙伴 于2025年4月提出. 其核心目标是让智能体通过标准化的通信方式, 安全地交换信息, 分配任务并协同执行复杂流程. 

* 智能体名片: 智能体通过JSON格式的智能体名片声明自身能力, 客户端智能体根据需求选择最适合的远程智能体. 
* 任务是核心概念, 它代表了一个agent需要完成的工作单元, 是agent之间协作的基本载体. 一个具体的代办事项或者指令, 可以由一个或者多个agent协作完成. 任务在执行过程中会经过不同的状态, 如提交, 进行中, 需要输入, 完成, 失败, 取消等, 其状态会持续跟踪和更新. 一个agent可以将任务委托给另一个agent去执行. 任务完成后, 通常会产生artifact, 即任务的输出结果. 
* 支持多模态通信: 支持文本, 音频, 视频流等多种形式, 并通过用户体验协商机制确定内容格式(如网页表单, 内联框架).
* 安全与扩展性: 基于HTTP, SSE, JSON-RPC等现有的标准构建, 集成企业级认证和授权机制, 确保数据安全. 

和MCP的区别:

| 维度 | MCP (Model Context Protocol) | A2A (Agent-to-Agent) |
| :--- | :--- | :--- |
| 核心定义 | AI模型与外部数据/工具连接的接口标准 | 多个独立智能体之间通信与协作的交互模式 |
| 主要目标 | 能力扩展: 让AI能"看见"文档, "使用"工具 | 任务分工: 通过多智能体协作解决复杂流程 |
| 连接对象 | AI 应用 <---> 本地/远程资源 (Server) | 智能体 (Agent) <---> 智能体 (Agent) |
| 通信逻辑 | C/S 架构: 客户端请求上下文或调用工具, 服务器响应 | 网状/链式架构: 任务接力, 辩论, 投票或分发 |
| 通俗类比 | USB-C 接口: 电脑(AI)通过标准接口连接打印机, 硬盘(工具) | 公司团队: 产品经理(Agent A)把需求传给程序员(Agent B) |
| 典型场景 | Cursor 读取本地代码库, Claude Desktop 操作 SQL 数据库 | AutoGen/CrewAI 团队协作, 复杂任务编排 |

## 什么是MCP

MCP是Model Context Protocol的缩写, 由Anthropic于2024年11月开源发布, 旨在为AI大模型与外部工具, 数据源之间的交互提供标准化接口, 类似AI领域的USB-C通用连接标准. 核心是给大模型提供一套标准语言, 来向外部系统发送请求, 拿取结果, 再将这些结果安全地塞到模型的上下文里面, 解决之前连接一个新的数据源或者应用就要单独对接一次的痛点, 改成只要对接MCP标准, 就能被各种支持MCP的模型和应用复用. MCP生态里面主要有三类角色, Host/Client, Server, LLM模型本身. 当模型需要额外信息或者执行操作的时候, 由客户端按照MCP规范向某个MCP服务器发送JSON-RPC请求, 对方完成实际操作之后, 把结构化结果返回, 再被送进模型上下文中用于生成更好的回答和行动.

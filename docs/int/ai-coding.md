## README

主要分为8个部分: 

1. 项目名称/背景: 这个项目是做什么的, 应用场景是什么
2. 题目目标: 最终要实现什么能力, 核心产出是什么
3. 输入/输出要求: 输入来自哪里, 输出成什么格式, 比如CLI, JSON, Markdown, 网页, API
4. 功能要求: 必须实现哪些功能, 哪些是加分项
5. 技术约束: 指定语言, 框架, 数据库, 依赖机制, 目录结构等
6. 运行方式: 如何安装依赖, 如何启动, 命令怎么写
7. 测试/验收标准: 怎么证明功能正确, 是否要求单测, 样例, 覆盖率
8. 交付物清单: 最后要提交哪些文件, 比如源码, README, USAGE, DESIGN, REPORT, 测试结果. 

## 提示词

## 1. 需求拆解

```text
请基于README.md拆解需求, 不要写代码. 

请输出:
1. 项目的一句话总结
2. P0/P1/P2 需求划分
3. 每个需求的验收标准
4. 最核心的业务主链路
5. 最小可交付 MVP
6. 哪些功能必须实现(必做)
7. 哪些功能可以暂时不做
8. 风险, 不确定点和需要确认的问题

要求:
- 不要扩展 README.md 没有要求的功能
- 优先保证 P0 功能可运行, 可测试, 可交付
- 如有不确定点, 请给出合理默认假设

保存为MVP.md
```

---

## 2. 架构设计

```text
请基于 README.md, MVP.md 设计架构, 不要写代码. 

请输出:
1. 技术栈
2. 目录结构
3. 核心模块划分
4. 数据模型
5. 接口/命令格式
6. 错误处理策略
7. 配置和环境变量设计
8. 测试方案
9. 不做哪些过度设计

要求:
- 优先简单可运行
- 不要过度设计
- 不要增加 MVP.md 没要求的功能

保存为DESIGN.md
```

---

## 3. 实现计划

```text
请基于 README.md, MVP.md, DESIGN.md 拆分实现阶段. 

每个阶段请输出:
1. 阶段目标
2. 实现内容
3. 涉及哪些文件
4. 新增哪些文件
5. 修改哪些已有文件
6. 如何运行
7. 如何测试
8. 如何调试
9. 对应 MVP.md 中的哪个要求
10. 完成该阶段的验收标准


要求:
- 每个阶段只做一件主要事情
- 优先完成 P0 主链路
- 不要加入无关功能

保存为MODULE.md
```

---

## 4. 写代码

```text
根据README.md, MVP.md, DESIGN.md, MODULE.md, 请实现 MODULE.md 中第 5 个阶段. 

要求:
1. 只做当前阶段
2. 先说明本阶段目标和文件清单
3. 新文件给完整内容
4. 旧文件给修改后的完整内容或 patch
5. 代码必须可运行
6. 写完后运行测试
7. 输出测试结果
8. 输出测试报告, 分析失败的测试用例, 给出修复方案

不要提前实现后续阶段. 
```

---

## 5. 联调

```text
请对已完成模块做联调. 

要求:
1. 检查接口是否一致
2. 运行完整主流程
3. 根据MVP.md的验收标准检查结果
4. 输出命令, 日志, 结果
5. 如失败, 给出最小修复方案, 并指明对应模块
```
